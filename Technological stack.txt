# Tech Stack & Dependency Document for the Website

## 1. Technology Objective

The website shall provide the operational interface for the **AI-Based Forecast Bust Detection System**, connecting users to forecast data, AI predictions, confidence scores, historical error analytics, explanations, and alerts.

The recommended architecture is:

```text
┌─────────────────────────────────────────────────────────────┐
│                    WEB FRONTEND                              │
│ React + Vite + TypeScript + Tailwind CSS                   │
│ Leaflet + Recharts + Axios                                 │
└──────────────────────────┬──────────────────────────────────┘
                           │ REST / JSON
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                    BACKEND API                              │
│ FastAPI + Python                                            │
│ Authentication + Validation + Business Logic               │
└──────────────┬──────────────────────┬───────────────────────┘
               │                      │
               ▼                      ▼
┌──────────────────────┐   ┌─────────────────────────────────┐
│ PostgreSQL + PostGIS │   │ ML / AI Layer                   │
│ Forecasts            │   │ XGBoost / Scikit-learn           │
│ Observations         │   │ SHAP                             │
│ Regions              │   │ Probability Calibration         │
│ Predictions          │   │                                  │
└──────────────────────┘   └─────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────────┐
│ Weather Data Sources                                        │
│ NWP Forecasts • Observations • Reanalysis • GeoJSON        │
└─────────────────────────────────────────────────────────────┘
```

# 9. Geographic Data

The website should consume GeoJSON rather than hard-code geographic boundaries.

Example:

```json
{
  "type": "Feature",
  "properties": {
    "region_id": "MH",
    "name": "Maharashtra"
  },
  "geometry": {
    "type": "Polygon",
    "coordinates": []
  }
}
```

This allows the map to be updated independently from the application logic.

# 20. Probability Calibration

The raw classifier probability should not automatically be treated as a reliable probability.

Recommended:

```text
XGBoost Classifier
       ↓
Probability Calibration
       ↓
Calibrated Bust Probability
       ↓
Confidence
```

Possible methods:

* Isotonic calibration
* Platt scaling / sigmoid calibration

## 47. Technology Selection Rationale

The stack is intentionally centered on **React + FastAPI + PostgreSQL/PostGIS + Python ML** because it cleanly separates the system into four responsibilities:

**React** → presents the forecast reliability information.

**FastAPI** → exposes the prediction and analytics APIs.

**PostgreSQL/PostGIS** → stores and queries temporal and geographic weather information.

**Python ML stack** → calculates forecast error, bust probability, confidence, and explanations.

This gives the team a relatively simple architecture while still supporting the complete flow required by the problem statement:

**Real Weather Data → NWP Forecast → Historical Error → ML Bust Detection → Confidence → Explainable AI → Interactive Website.**
