# User Journey / Workflow Document

## 1. Purpose

This document defines how users interact with the **AI-Based Forecast Bust Detection System** from opening the application through identifying, investigating, and interpreting forecast uncertainty.

The workflow is designed around the core operational question:

> **Where is the medium-range forecast likely to be unreliable, when is the risk highest, and why?**

---

# 2. Primary User Journey

```text
Open Application
       ↓
Dashboard
       ↓
Select Forecast Run
       ↓
Select Weather Variable
       ↓
Select Lead Day (D1–D10)
       ↓
View India Confidence Map
       ↓
Identify High-Risk Region
       ↓
Open Region Details
       ↓
Review Bust Probability
       ↓
Review Confidence Score
       ↓
Review Historical Error
       ↓
Review AI Explanation
       ↓
Compare 10-Day Reliability
       ↓
Review Alerts
       ↓
Take Analytical / Operational Action
```

---

# 3. User Roles

| Role            | Main Objective              | Typical Workflow                             |
| --------------- | --------------------------- | -------------------------------------------- |
| Meteorologist   | Assess forecast reliability | Dashboard → Map → Region → Explanation       |
| Weather Analyst | Study error patterns        | Analytics → Region → Historical Error        |
| Researcher      | Evaluate AI behavior        | Bust Detection → Explanation → Model Metrics |

# 4. Journey 1 — Daily Forecast Reliability Monitoring

### Goal

Quickly determine whether the current medium-range forecast contains regions or lead times with elevated uncertainty.

### Workflow

```text
Login / Open Dashboard
        ↓
Check Forecast Run
        ↓
Check Data Status
        ↓
Review Overall Confidence
        ↓
Select Day
        ↓
Inspect India Map
        ↓
Identify High-Risk Areas
        ↓
Open Region
        ↓
Review Explanation
```

### Step-by-step

| Step | User Action        | System Response                   |
| ---- | ------------------ | --------------------------------- |
| 1    | Open dashboard     | Latest forecast run displayed     |
| 2    | Check data status  | Current/stale/error status shown  |
| 3    | Select variable    | Map updates                       |
| 4    | Select Day 1–10    | Reliability values update         |
| 5    | Inspect map        | Region-wise confidence displayed  |
| 6    | Select region      | Region drawer opens               |
| 7    | Review probability | Bust probability displayed        |
| 8    | Review reasons     | AI explanation displayed          |
| 9    | Review history     | Historical error comparison shown |

# 5. Journey 2 — Identify a Forecast Bust

### Goal

Find a region where the current NWP forecast has a high probability of significant error.

```text
Dashboard
   ↓
Forecast Map
   ↓
Day 5
   ↓
Rainfall
   ↓
High-risk region
   ↓
Region Details
   ↓
Bust Probability
```

### Example

User selects:

```text
Variable: Rainfall
Lead Day: Day 5
```

The map identifies a region with:

```text
Bust Probability: 78%
Confidence: 22%
Risk: HIGH
```

The user then opens the region for investigation.

# 6. Journey 3 — Understand Why Confidence Is Low

### Goal

Provide an interpretable reason for the AI prediction.

```text
Region Selected
       ↓
AI Prediction
       ↓
Feature Contributions
       ↓
SHAP Explanation
       ↓
Human-readable Explanation
```

### Example

The interface shows:

**Bust Probability:** 78%

**Main contributing factors:**

1. High historical rainfall error
2. Large run-to-run forecast change
3. High ensemble spread
4. Elevated atmospheric variability

Then:

> **Interpretation:** The system estimates elevated forecast uncertainty because this region has historically experienced larger rainfall errors at this lead time, while the latest forecast has changed substantially and ensemble members show greater disagreement.

       ↓

       ↓

```text

Region: Maharashtra
Variable: Rainfall
Lead Day: D5

Bust Probability: 78%
Confidence: 22%

• Historical error
• Forecast run change

```

# 10. Journey 7 — Data Quality Problem

### Goal

Prevent users from interpreting unreliable AI output when the underlying data is incomplete.

```text
Dashboard
    ↓
Data Quality Warning
    ↓
Open Data Health
    ↓
Identify Affected Dataset
    ↓
Review Impact
```

Example:

```text
⚠ DATA QUALITY ISSUE

Observation data is incomplete.

Affected:
• 4 regions
• Rainfall
• Day 5–Day 7

AI confidence may be unavailable or degraded.
```

The system must not silently replace missing values with invented values.

# 15. User Decision Workflow

The system should support the following reasoning process:

```text
1. Is the forecast currently available?
             ↓
2. Is the data quality acceptable?
             ↓
3. Which lead day has higher uncertainty?
             ↓
4. Which region is affected?
             ↓
5. What variable is affected?
             ↓
6. How large is the bust probability?
             ↓
7. Why did the model assign this probability?
             ↓
8. Does historical evidence support the concern?
             ↓
9. Is there an active AI reliability alert?
             ↓
10. Review the forecast with appropriate caution
```

The system informs the user; it does not replace official meteorological judgment or official weather warnings.

---

# 16. State-Based Workflow

Each prediction can move through the following UI states:

```text
DATA AVAILABLE
      ↓
VALIDATED
      ↓
FEATURES READY
      ↓
AI PREDICTION
      ↓
CALIBRATED
      ↓
EXPLAINED
      ↓
DISPLAYED
      ↓
ALERT GENERATED (if threshold met)
```

Possible failure states:

```text
DATA MISSING
DATA STALE
DATA INVALID
MODEL UNAVAILABLE
PREDICTION UNAVAILABLE
```

The UI should explicitly communicate each failure state.

# 17. Primary Workflow Acceptance Criteria

| ID    | Workflow Requirement                                                              |
| ----- | --------------------------------------------------------------------------------- |
| WF-01 | User can open the latest forecast dashboard                                       |
| WF-02 | User can select a forecast variable                                               |
| WF-03 | User can select Day 1–Day 10                                                      |
| WF-04 | System updates the map based on selected lead day                                 |
| WF-05 | User can identify high-risk regions                                               |
| WF-06 | User can open regional forecast details                                           |
| WF-07 | System displays bust probability                                                  |
| WF-08 | System displays confidence score                                                  |
| WF-09 | System displays historical error information                                      |
| WF-10 | System provides an AI explanation                                                 |
| WF-11 | User can inspect 10-day confidence trends                                         |
| WF-12 | User can investigate AI reliability alerts                                        |
| WF-13 | System identifies stale/missing data                                              |
| WF-14 | System communicates model-health problems                                         |
| WF-15 | Prediction can be traced to forecast run and model version                        |
| WF-16 | Official weather warnings remain visually distinct from AI reliability alerts     |
| WF-17 | System does not generate fabricated predictions when required data is unavailable |

### Demonstration message

The complete user journey should demonstrate that the system can answer four questions:

**WHERE?** → India confidence map
**WHEN?** → Day 1–Day 10
**HOW UNCERTAIN?** → Bust probability / confidence
**WHY?** → Historical error + atmospheric/forecast features + explainable AI

This workflow directly connects the user interface to the core requirements of the problem statement.
