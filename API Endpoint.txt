# API Contract / Endpoint Document

**Project:** AI-Based Forecast Bust Detection for Medium-Range Weather Forecasts
**Problem Statement:** 26079 – MoES / NCMRWF
**API Style:** REST
**Base Path:** `/api/v1`
**Backend:** FastAPI + Python
**Data Format:** JSON
**Authentication:** Optional for hackathon MVP; API key/JWT for operational deployment

---

## 1. API Design Principles

| Principle     | Specification                                     |
| ------------- | ------------------------------------------------- |
| REST          | RESTful HTTP endpoints                            |
| Versioning    | `/api/v1`                                         |
| Format        | JSON                                              |
| Time          | UTC internally, ISO-8601                          |
| Coordinates   | WGS84 latitude/longitude                          |
| Probability   | 0–1 internally, 0–100% in UI                      |
| Confidence    | 0–1 internally, 0–100% in UI                      |
| Errors        | Standard HTTP status codes                        |
| Pagination    | Required for large historical datasets            |
| Documentation | OpenAPI/Swagger through FastAPI                   |
| Traceability  | Prediction contains model/data source information |

# 7. Forecast API

## `GET /api/v1/forecast`

Returns NWP forecast information.

### Query Parameters

| Parameter      | Required | Example                |
| -------------- | -------- | ---------------------- |
| `region_id`    | Yes      | `MH_MUM`               |
| `lead_day`     | No       | `5`                    |
| `variable`     | No       | `rainfall`             |
| `forecast_run` | No       | `2026-09-28T00:00:00Z` |

### Example

```http
GET /api/v1/forecast?region_id=MH_MUM&lead_day=5&variable=rainfall
```

### Response

```json
{
  "region_id": "MH_MUM",
  "forecast_run": "2026-09-28T00:00:00Z",
  "valid_time": "2026-10-03T00:00:00Z",
  "lead_day": 5,
  "variable": "rainfall",
  "value": 84.2,
  "unit": "mm",
  "source": "NWP"
}
```

# 22. Standard Error Contract

Every endpoint should return a consistent error structure.

### Example `400 Bad Request`

```json
{
  "error": {
    "code": "INVALID_PARAMETER",
    "message": "lead_day must be between 1 and 10",
    "field": "lead_day"
  }
}
```

### Example `404 Not Found`

```json
{
  "error": {
    "code": "REGION_NOT_FOUND",
    "message": "Region MH_XXX was not found"
  }
}
```

### Example `503 Service Unavailable`

```json
{
  "error": {
    "code": "MODEL_UNAVAILABLE",
    "message": "AI prediction service is temporarily unavailable"
  }
}
```

# 23. HTTP Status Codes

| Status | Meaning                         |
| -----: | ------------------------------- |
|  `200` | Successful GET                  |
|  `201` | Resource created                |
|  `202` | Request accepted for processing |
|  `400` | Invalid request                 |
|  `401` | Authentication required         |
|  `403` | Access denied                   |
|  `404` | Resource not found              |
|  `409` | Duplicate/conflicting resource  |
|  `422` | Validation error                |
|  `429` | Rate limit exceeded             |
|  `500` | Internal server error           |
|  `503` | Service/model/data unavailable  |

# 25. MVP API Set

For the hackathon, you don't need to implement every endpoint immediately.

Build these first:

```text id="0xqzgm"
1. GET  /api/v1/health

2. GET  /api/v1/regions

3. GET  /api/v1/forecast

4. GET  /api/v1/confidence

5. GET  /api/v1/confidence/10day

6. GET  /api/v1/map/confidence

7. POST /api/v1/predict/bust

8. GET  /api/v1/explanation/{prediction_id}

9. GET  /api/v1/analytics/error

10. GET /api/v1/alerts
```

These ten endpoints are enough to demonstrate the complete flow:

**Weather Data → NWP Forecast → ML Bust Detection → Confidence → Explanation → India Map → Alerts.**

For the actual implementation, **FastAPI will automatically generate Swagger/OpenAPI documentation**, so the frontend team can test these contracts directly at the API documentation endpoint.
