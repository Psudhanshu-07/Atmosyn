# UI/UX Specification

## AI-Based Forecast Bust Detection for Medium-Range Weather Forecasts

### 1. UI/UX Objective

The UI shall provide a **simple, operational web dashboard** that allows meteorologists, researchers, and administrators to quickly understand:

* Where the NWP forecast may be unreliable
* Which forecast lead day has higher bust probability
* The confidence level for each region
* Which weather variables are contributing to uncertainty
* How current forecast behavior compares with historical errors
* Why the AI has assigned a particular confidence level
* Whether data/model quality is sufficient for the prediction

The interface should prioritize **fast interpretation over visual complexity**.

---

# 2. Target Users

| User            | Primary Need                               | Main Screens                            |
| --------------- | ------------------------------------------ | --------------------------------------- |
| Meteorologist   | Identify unreliable forecast regions       | Dashboard, Forecast Map, Region Details |
| Weather Analyst | Investigate historical forecast errors     | Analytics                               |
| Researcher      | Understand ML predictions and explanations | AI Bust Detection, Analytics            |
| Operations User | Monitor current forecast reliability       | Dashboard, Alerts                       |
| Administrator   | Monitor data/model health                  | System/Data Quality                     |

---

# 3. Design Principles

### 3.1 Operational First

The most important information should be visible immediately:

> **Region → Lead Day → Bust Probability → Confidence → Reason**

### 3.2 Map-Centric Visualization

Because the problem is spatial, the India map should be the primary visualization.

### 3.3 Explainable AI

Every AI prediction should answer:

> **“Why is confidence low?”**

Example:

> **Low confidence because:**
> Historical rainfall error is high + current forecast changed significantly from previous run + ensemble spread is large.

### 3.4 No False Precision

The UI should avoid presenting AI output as an official forecast.

Use:

**“AI Bust Probability: 78%”**

rather than:

**“Forecast will be wrong: 78%.”**

### 3.5 Progressive Disclosure

Show a simple summary first, with detailed meteorological information available through drill-down.

# 17. Human-Readable AI Explanation

Example UI:

> **Why is confidence low?**
>
> The rainfall forecast for Day 5 has elevated bust probability because historical rainfall errors for this region and lead time are high. The latest forecast also differs substantially from the previous forecast run, while ensemble members show relatively large disagreement.

The explanation must be generated from actual model features.

The UI should not invent meteorological causes.

# 28. Methodology Content

### NWP Forecast

Current medium-range numerical weather prediction data.

### Historical Error

Past forecast versus observation differences.

### AI Model

Machine-learning models identify patterns associated with larger forecast errors.

### Bust Probability

Probability that the current forecast exceeds the configured significant-error threshold.

### Confidence

Prototype reliability indicator derived from calibrated bust probability.

```text
Confidence = 1 − Bust Probability
```

### Explainability

SHAP-based feature contribution identifies the strongest factors influencing the prediction.

# 29. Color & Visual Language

The interface should use a restrained operational visual language.

### Risk colors

| Risk             | Suggested visual |
| ---------------- | ---------------- |
| Very Low         | Green            |
| Low              | Light green      |
| Moderate         | Amber            |
| High             | Orange           |
| Very High        | Red              |
| Data unavailable | Gray             |

Do not rely on color alone.

Every risk state should also contain:

* Text label
* Numerical probability
* Optional icon/pattern

Example:

```text
● HIGH
78%
```

This improves accessibility.

# 36. Accessibility

The UI should target WCAG 2.1 AA-level practices.

Requirements:

* Keyboard navigation
* Visible focus indicators
* Sufficient text contrast
* Color-independent risk indication
* Accessible chart labels
* Tooltips with text alternatives
* Screen-reader-friendly controls
* Minimum practical touch target size
* No critical information communicated through color alone

        ↓

        ↓

This creates a clear story:

## Final UI/UX Principle

The dashboard should feel less like a generic weather website and more like an **operational forecast-reliability workstation**:

> **“Show me where the forecast may fail, how likely that is, how confident the system is, and why.”**

The central user experience should therefore remain:

**India Map → Day/Variable → Bust Probability → Confidence → Explanation → Historical Evidence.**
